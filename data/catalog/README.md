# Каталог MVP и аудит источников

Активный каталог MVP: `city/catalog.jsonl`, версия `city-osm-v2`, **281 объект**.
Предыдущий срез из 40 мест остаётся в `data/demo/` для воспроизводимости.

## Аудит задания

В `db/seed/main.csv` — 174 записи, в `addition.csv` — 85. Все 259 записей имеют
заполненные ID, название, категорию, описание, адрес и корректно разбираемый WKT
`POINT (longitude latitude)`. ID не повторяются ни внутри файлов, ни между ними.
Проверка диапазонов не доказывает точность точки входа или принадлежность
административной границе города.

В датасете отсутствуют отдельные поля подтверждённых часов, длительностей,
допусков, возрастной пригодности, цен и конкретных сеансов. Даты содержательной
проверки также отсутствуют. Это справочник объектов для дальнейшего обогащения,
не набор готовых меток обучения рекомендательной системы.

Принятые решения записаны в `seed_review_decisions.json` и привязаны к SHA-256
исходных CSV. Изменение входных байтов требует повторной проверки решений.

- 165 исходных записей включены в городской каталог.
- Две записи парка «Швейцария» объединены под `place:main:67`; строка 225
  сохранена как alias в `city/source_mapping.csv`. В исходных описаниях различаются
  площади (380 и 52 га): область измерения не установлена, площадь не стала
  нормализованным фактом; предупреждение передаётся в рекомендации.
- Памятники Горькому 51 и 122 сохранены отдельно: это разные адреса и скульптуры.
- Шесть школ удержаны до появления конкретных открытых программ.
- Дирекция парков удержана как организация без самостоятельной активности.
- Шуховская башня на Оке в Дзержинске сохранена в исходнике, но отложена для
  отдельного загородного сценария. Она находится в широких bounds маршрутизатора,
  поэтому один такой bbox не заменяет проверку географического смысла адреса.
- Заголовок 242 уточнён по точной цитате собственного описания: это библиотека
  Короленко. Исходное название и основание исправления сохранены в provenance.
- 85 записей `addition` остаются объектами карты, а не отдельными развлечениями.
  У 38 из них координаты совместно используются 17 группами объектов, главным
  образом произведениями в одной станции метро. Такие точки не удаляются как дубли
  и не считаются проверенными входами.

По сравнению с прежним срезом сохранены 37 мест, добавлены 128 и отложены 3 школы.
Исходные CSV не изменены. Темы и форматы остаются эвристическими; неизвестные
семейные условия не преобразованы в разрешения.

## Расширение из OSM

К исходному этапу из 165 мест добавлены 116 объектов из уже сохранённого снимка
`data/enriched/osm_nizhny_1000/catalog.jsonl`:

| Тип | Добавлено |
|---|---:|
| Музеи и галереи | 27 |
| Детские площадки | 35 |
| Культурные площадки | 18 |
| Достопримечательности | 28 |
| Библиотеки | 7 |
| Парк развлечений | 1 |

Правила закреплены в `osm_expansion_policy.json` и привязаны к SHA-256 снимка.
Сохранены все 165 мест первого этапа. Новые места имеют отдельные ID `place:osm:…`,
источник и исходную дату получения. Булевы свойства из OSM сохраняют evidence;
опубликованная сырая строка часов не становится подтверждённым расписанием.
Возраст и допуск ребёнка остаются неизвестными, длительность посещения — оценкой.

Безымянные площадки включаются только при явном `access=yes`; известные частные
объекты удерживаются. Рестораны, туалеты, скамейки и укрытия не становятся
развлечениями в initial-пуле. Мемориальные таблички и отдельные экспонаты не
создают новые самостоятельные посещения. Для неопределённых адресов и возможных
пересечений формируется очередь; близость сама по себе не создаёт связь сущностей.

Результат разбора всех 1000 входных объектов — `city/osm_expansion_review.json`.
82 возможных пересечения отложены без утверждения тождества. Для 128 безымянных
площадок требуется уточнение доступа. Известные неоднозначные записи «Кварков»,
литературного музея и старого адреса музея шоколада также оставлены на проверку.

Новые записи несут `OSM_SOURCE_UNVERIFIED`, а площадки без конкретной программы —
`PROGRAM_NOT_CONFIRMED`. Эти предупреждения требуют подтверждения перед apply.
Ссылки на сайты остаются кандидатами для проверки домена в `city/parsing_queue.csv`.
Источник и атрибуция OSM описаны также в `data/README.md`.

## Дополнительная выгрузка пользователя

Файл `_select_cs_id_cs_address_cs_coordinate_cs_description_cs_title_c.csv`
содержит **259 логических CSV-записей** с многострочными описаниями. Все шесть
полей каждой записи полностью совпадают с объединением `main` и `addition`:
новых объектов — 0, изменённых записей — 0. Он зарегистрирован в
`import_registry.json`; исходный снимок сохранён в игнорируемом `data/raw/user_imports/`.
В `city/source_audit.json` сохранены результат сравнения и SHA-256.

Повторное добавление той же выгрузки не увеличивает количество мест. Новые ID
из будущих файлов попадают в `new_record_candidates`, а изменение существующего
ID — в `id_conflicts`, для разбора до публикации.

## Сопоставление с OSM

В старом `source_dataset_mapping.csv` было 116 связей по правилу `name_or_80m`.
У 110 названия различаются, у 40 совпавший OSM-узел имеет тип инфраструктуры или
ресторана вместо культурного объекта. Различие названий само по себе не доказывает
ошибку, но близость к туалету или скамейке не устанавливает идентичность объекта.
Эти связи не используются для переноса фактов в городской каталог.

Обновлённый matcher требует нормализованное совпадение названия, совместимый тип,
расстояние до 300 м и отсутствие неоднозначности. Получено 5 кандидатов в
`city/osm_source_candidates.csv`; они также требуют ручной проверки. Старый файл
оставлен как исторический результат, его аудит сохранён в `city/source_audit.json`.
Будущая пересборка OSM использует новое правило.

## Воспроизведение

```bash
.venv/bin/python scripts/prepare_city_catalog.py
# Зарегистрировать другую полученную CSV-выгрузку:
.venv/bin/python scripts/prepare_city_catalog.py --import-csv /absolute/path/to/export.csv
PYTHONPATH=models .venv/bin/python -m unittest discover -s models -p 'test_*.py'
PYTHONPATH=models .venv/bin/python -m unittest discover -s models -p test_ml_boundaries.py
```

Основные результаты: `city/manifest.json`, `city/coverage_report.json`,
`city/source_audit.json`, `city/source_mapping.csv`, `city/parsing_queue.csv`.
Существующие зарегистрированные снимки повторно проверяются при пересборке, если
сохранились в `data/raw/user_imports/`. Сам каталог воспроизводится из файлов Git.

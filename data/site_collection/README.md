# Первая партия данных сайтов

Для восстановления описаний OSM добавлен пакетный запуск
`scripts/restore_osm_descriptions.py` и разбор открытого туристического справочника
`scripts/discover_tourism_descriptions.py`. `scripts/recover_osm_descriptions.py`
сохраняет исходные фрагменты с evidence, а `scripts/export_all_places.py` собирает
полный датасет мест в `outputs/all_places_v1/`. Состав и ограничения описаны в
[`README полного датасета`](../../outputs/all_places_v1/README.md).
Ключи берутся из локального `.env` только новым пакетным runner; ниже оставлена
документация прежнего CLI первого сбора.

Восстановлено 20 ноября 2026 года из корневых `continuation_handover.md`,
`data_enrichment_ml_task.md` и архива продолжения.

## Полученный результат

- Загружены 3 страницы: GRANAT `/restoran`, GRANAT `/detyam/`, «Соляная биржа» `/`.
- Выделены 20 утверждений официальных сайтов для 2 ресторанов и их игровых комнат.
- Каждая цитата проверена на точное присутствие в сохранённом тексте.
- JSONL и CSV: `data/processed/site_collection/first_batch/facts.jsonl` и `facts.csv`.
- Заполненность и неизвестные поля: `facts_report.json`; состояние загрузки: `report.json`.
- Тексты, JSON-LD, URL, время загрузки и SHA-256 исходного HTML: подкаталог `pages/`.
- Все 3 запроса НГХМ завершились `ConnectTimeout` на TLS handshake. Это ограничение
  текущего подключения, а не доказательство недоступности сайта для посетителей.
  Архивный extraction `data/processed/catalog/nizhny_art_museum_rules.json` сохранён;
  его дата получения не изменена и с новой партией он не смешан.

`reviewed_claims.json` содержит редакционно выделенные значения и цитаты.
Это утверждения сайта, а не подтверждение условий на месте. `content_verified_at`
остаётся `null`. Утверждение о бебиситтере не обещает непрерывный присмотр;
воскресная анимация не превращена в конкретный сеанс. Возраст комнаты не
распространяется на весь ресторан. Часы ресторана не назначены кухне или комнате.
Возрастная надпись 18+ в футере сайта «Соляной биржи» не назначена ограничением ресторана.

Сопоставление с каноническим каталогом ещё не выполнено (`canonical_place_id=null`).
Поля ресторанов пока хранятся внутренними наблюдениями: текущая `SiteExtraction`
не описывает все семейные удобства. Для передачи в API нужен отдельный согласованный
контракт. Снимки сайтов и результаты находятся в игнорируемом `data/processed/`.

## Повторный запуск

Из корня репозитория, после установки `requirements-ml.txt` в виртуальное окружение:

```bash
# Если локальный реестр ещё не восстановлен:
cp data/site_collection/reviewed_registry.json data/source_registry.json
.venv/bin/python scripts/collect_sites.py
.venv/bin/python scripts/export_reviewed_site_facts.py
```

Если реестр уже существует, добавить выбранные sources, сохраняя свои записи.
`reviewed_registry.json` содержит только три рассмотренных домена. Robots.txt
проверяется заново fetcher-ом при каждой сетевой загрузке. Непроверенные 173 домена
из source discovery автоматически не включаются.

Worker последовательно получает только явно перечисленные URL, максимум 10 за запуск,
с интервалом начала запросов не менее 3 секунд. Он не переходит по ссылкам сайта.
Успешные снимки сохраняются сразу и повторно используются; ошибочные страницы
запрашиваются снова при следующем запуске. `--refresh` принудительно обновляет снимки.
Наличие хотя бы одной ошибки даёт exit code 1; остальные результаты сохранены.

## GigaChat

Ключа в переданном пакете нет. `.env` автоматически этими CLI не читается.
После безопасной настройки переменных окружения можно запустить:

```bash
export GIGACHAT_SCOPE=GIGACHAT_API_B2B
export GIGACHAT_MODEL=GigaChat-3-Pro
export GIGACHAT_CA_BUNDLE="$PWD/infra/docker/certs/russian_trusted_root_ca_pem.crt"
# GIGACHAT_CREDENTIALS задать отдельно, не сохранять в Git.
.venv/bin/python scripts/collect_sites.py --extract
```

В локальном Python используется `GIGACHAT_CA_BUNDLE`; `GIGACHAT_CA_FILE` в Compose
обозначает путь сертификата на хосте. Это разные уровни конфигурации.
LLM extraction сохраняется отдельно от редакционно проверенных наблюдений.
Совпадение SHA-256 позволяет пропустить уже обработанную страницу.

## 0. Что делаем

Сейчас семья и параметры поездки зашиты в `frontend/js/app.js` (`FAMILY`, `TRIP_INPUT`). Нужно заменить это на экраны:

**Один раз:** вход/регистрация → анкета семьи (3 шага).
**Перед каждой поездкой:** даты и старт → подбор мест свайпами (уже есть, `pick.js`) → пожелания и итог → предпросмотр маршрута → сохранить.

Макет — 8 экранов (холст «Регистрация, анкета и новая поездка»; у Артёма есть ссылка). Ниже всё, что на них есть, текстом — этого достаточно для вёрстки.

- `examples/family-onboarding.json` — пример первого сохранения анкеты.
- `frontend/js/api.js` — сессия и CSRF (`openSession`, `call`), создание поездки, preview/apply. **Расширять его, а не писать второй HTTP-клиент.**
- `frontend/js/app.js` — точка входа, вкладки, `TRIP_INPUT`.
- `frontend/js/pick.js` + `css/pick.css` + секция `#screen-pick` в `index.html` — свайпы мест («тиндер»), карточки из `frontend/data/cards.json`. Готово, переиспользовать.
- `frontend/css/app.css` — токены цветов (`--now`, `--kid`, `--ink`…), шрифты Nunito/Prata из `css/fonts.css`. Новых цветов не вводить.

Ручки бэкенда (все под `/api/v1`, один origin через прокси, cookie HttpOnly):

| Ручка | Зачем |
|---|---|
| `GET /session` | cookie + `csrf_token`, `authenticated`, `user`, `onboarding_completed` |
| `POST /auth/register`, `POST /auth/login` | `{ email, password }` → **новый** `csrf_token`, заменить в памяти |
| `POST /auth/logout`, `GET /auth/me` | выход (новая гостевая сессия + новый CSRF), профиль аккаунта |
| `GET /profile/family` | анкета; `404 PROFILE_NOT_FOUND`, если её нет. **Только для аккаунта** (гость → `401 AUTH_REQUIRED`) |
| `PUT /profile/family` | сохранить анкету: первый раз `expected_version: 0` → 201; потом текущая `version` → 200; `409 VERSION_CONFLICT` → перечитать |
| `GET /reference-data` | `interest_options` (id + label), допустимый возраст детей |
| `POST /trips/from-profile` | поездка из анкеты (аккаунт) — нужен `Idempotency-Key` |
| `POST /trips` | поездка с полным `TripInput` (гость) — нужен `Idempotency-Key` |
| `POST /trips/{id}/previews` → `.../apply` | построить вариант (`generate_plan`) и сохранить |
| `GET /trips` | мои поездки |

Все мутации: заголовки `X-CSRF-Token`, `Content-Type: application/json`.

## 2. Логика запуска (машина состояний)

```
GET /session
├─ authenticated = false и нет флага «гость» в localStorage  → экран «Вход/регистрация»
├─ authenticated = true и onboarding_completed = false        → анкета (3 шага)
├─ гость и нет локальной анкеты                               → анкета (3 шага)
├─ есть сохранённая поездка (trip-id в localStorage, не просрочена) → основной интерфейс (как сейчас)
└─ иначе                                                       → «Новая поездка»
```

- **Гость** («Продолжить без входа»): анкета хранится в `localStorage` (ключ `family-profile-v1`, обёртка `try/catch`), поездка создаётся через `POST /trips` с полным `TripInput`. Гостевая сессия живёт 24 часа — показать это пользователю (экран 8).
- **Вход после гостя**: бэкенд сам переносит гостевые поездки в аккаунт. Фронт после входа делает `PUT /profile/family` из локальной анкеты (`expected_version: 0`, если `GET` вернул 404).
- Уже авторизованному `register/login` отвечают `409 ALREADY_AUTHENTICATED` → сначала `logout`.
- В профиле (новая кнопка в шапке или во вкладке «Альбом» — где удобнее) — «Изменить анкету» и «Выйти».

## 3. Экраны

Общее: мобильная колонка `.app` (max-width 480), фон экранов анкеты `--bg`, карточки белые со скруглением 20 px, основная кнопка внизу — синяя `--now`, высота 54. Кнопка «‹» назад 44×44. Сверху — «Анкета семьи · шаг N из 3» / «Новая поездка · шаг N из 3» и полоска прогресса из 3 частей (анкета — синяя, поездка — оранжевая `--kid`). Нижнее меню (`.tabbar`) на этих экранах скрыто. Все кнопки ≥ 44 px, выбранность — `aria-pressed`, переключатель — `role="switch"`.

### Экран 1. Вход и регистрация
- Иллюстрация (маршрут-пунктир, кремль) — можно простой inline SVG.
- Заголовок (Prata): «Семейные прогулки по Нижнему». Подзаголовок: «Маршрут под возраст и интересы ваших детей. Анкету заполните один раз — дальше только даты.»
- Сегмент «Регистрация | Вход».
- Поля «Почта» (`type=email`, `autocomplete=email`) и «Пароль» (`autocomplete=new-password`/`current-password`, кнопка-глаз).
- Подсказка при регистрации: «Не короче 15 символов. Удобно фразой: „едем в нижний всей семьёй“». Валидация на клиенте: 15–128 символов, не только пробелы; почта — непустая с `@`. Ошибки бэкенда показывать текстом `error.message` под формой. `429` — «Слишком много попыток, подождите N с» из `Retry-After`.
- Кнопки: «Создать аккаунт» / «Войти»; ссылка «Продолжить без входа»; мелкий текст «Без входа поездка живёт сутки на этом телефоне. Войдёте позже — она перейдёт в аккаунт.»
- Пароль никуда не сохранять, кроме отправки.

### Экран 2. Анкета, шаг 1 — «Кто едет?»
- Подзаголовок: «Заполняете один раз. Поменять можно в профиле.»
- **Взрослые** — степпер − N + (1…10), по умолчанию 2 → `family.adult_count`.
- **Дети** — счётчик «− N +» (как у взрослых), от 1 до 10 детей от 3 до 11 лет
- Для каждого ребёнка карточка: оранжевый номер, поле «Как обращаться в детском режиме (необязательно)», «Возраст, лет» — 9 кнопок 3…11 в одну строку (`grid` на 9 колонок) → `children[i].age_years`.
- `child_id` генерирует клиент (`child-1`, `child-2`) и **не меняет** при редактировании. `height_cm: null`.
- **Имя ребёнка в бэкенд НЕ отправлять** (в контракте поля нет, и это лишние данные о ребёнке). Хранить только в `localStorage` рядом с `child_id`; детский режим (`kid.js`, сейчас «Маша» захардкожена в `app.js`) берёт имя оттуда, если пусто — «Ребёнок 1».

### Экран 3. Анкета, шаг 2 — «Что интересно детям?»
- Подзаголовок: «Отметьте для каждого — можно несколько. Подберём места так, чтобы скучно не было никому.»
- По карточке на ребёнка: аватар-буква, имя, «7 лет · выбрано 3».
- Чипсы (множественный выбор): **Животные, Эксперименты, История, Творчество, Техника, Активные игры, Природа** и отдельно **«Пока не знаем»** (пунктирная рамка). «Пока не знаем» снимает остальные и наоборот → `interest_ids: []`.
- Подпись под «Пока не знаем»: «Подберём то, что обычно нравится детям этого возраста.»
- **Список берётся из `GET /reference-data` → `interest_options`** (id + label), а не хардкодится. Сейчас бэкенд отдаёт только `history / science / play` — см. «Открытые вопросы». Пока список не расширили, рисовать то, что пришло; для демо допустим локальный fallback-список из макета **с id, согласованными с ML** (Вильдан).

### Экран 4. Анкета, шаг 3 — «А что интересно вам?»
- **Взрослым**: чипсы **История, Архитектура, Музеи, Прогулки, Природа, Местная кухня** → `adult_interest_ids` (тоже из `interest_options` после согласования).
- **Темп прогулок** — 3 кнопки с подписями: «Спокойный — больше привалов» → `relaxed`, «Обычный — как все» → `standard`, «Активный — успеть больше» → `intensive`. По умолчанию `relaxed`.
- **Пожелания и ограничения — необязательно**: `<textarea>` до 2000 символов → `wishes` (пусто → `null`). Быстрые чипсы дописывают фразу в поле: «Избегать лестниц», «Ребёнок не любит шум», «Частые перерывы», «Едем с коляской», «Нужен тихий отдых».
- `load_limits`: `max_walk_distance_m_per_day: null` (возрастной дефолт бэкенда), `max_continuous_walk_duration_sec: null`, `restaurant_walk_reserve_m_per_day: 0`. Числовые настройки не показываем.
- Кнопка «Сохранить анкету», подпись «Больше не спросим. Поменять можно в профиле.»
- Аккаунт → `PUT /profile/family` (тело как `examples/family-onboarding.json`), запомнить `version`. Гость → `localStorage`.

### Экран 5. Новая поездка, шаг 1 — «Когда и откуда гуляем?»
- **«Вы уже в Нижнем?»** — «Уже здесь» → `planning_context: "in_city"`, «Только собираемся» → `"before_arrival"`.
- **Даты прогулок** — мини-календарь месяца (неделя с понедельника), выбор диапазона, прошедшие дни неактивны, сегодня обведено. Итог строкой: «Сб 21 — Вс 22 ноября · 2 дня». 1–14 дней (лимит `days`).
- **Сколько гуляете в день** — «до 3 часов» / «4–5 часов» / «весь день» → `duration_budget_sec` = 3 ч / 5 ч / 8 ч [Предложение, согласовать с Максимом].
- **Откуда начинаете день** — поле + кнопка «Моё местоположение» (`navigator.geolocation`). **Геокодера адресов в проекте нет** → для демо: геолокация, выбор точки на карте (MapLibre уже подключён) и 3–5 готовых точек (например, «Площадь Минина и Пожарского» — она уже есть в `app.js`). Точка → `start_point: { coordinates: [lon, lat], label }`.
- **Переключатель «Возвращаться сюда вечером»** (по умолчанию вкл.): вкл. → `end_point = start_point` для каждого дня (кольцевой маршрут); выкл. → показать второе поле «Где заканчиваете день».
- `available_window`: `in_city` и сегодняшний день — с текущей минуты до 21:00 (как сейчас в `app.js`); иначе 10:00–20:00 по Москве [Предложение]. `meal_window: null`, `rest_budget_sec: 0`, `timezone: "Europe/Moscow"`, `city_id: "nizhny_novgorod"`.
- Кнопка «Дальше: выбрать места».

### Экран 6. Новая поездка, шаг 2 — подбор мест (есть в `pick.js`)

- [Предложение] На карточке — чипсы совпадения с анкетой: «Маше: история», «Вам: архитектура» (если категория/теги карточки совпадают с интересами).

### Экран 7. Новая поездка, шаг 3 — «Что-то особенное в этот раз?»
- `<textarea>` «Пожелания на эту поездку», **предзаполнено пожеланиями из анкеты**. Подпись: «Пожелания из анкеты уже здесь. Допишите, что нужно именно сейчас — анкета не изменится.»
- → `request_text`: текст поля; если пользователь ничего не менял — `null` (бэкенд возьмёт пожелания анкеты); очистил — `""`. **В demo-режиме бэкенда свободный текст запрещён**: если `reference-data.capabilities.free_text === false`, отправлять `request_text: ""` и показать «Пожелания пока учитываются не полностью».
- Блок **«Что мы учтём»** — строки «Семья / Интересы / Когда / Старт / Обязательно» со ссылкой «Изм.» на нужный экран.
- Кнопка «Построить маршрут» → аккаунт: `POST /trips/from-profile` с `expected_profile_version`; гость: `POST /trips` с полным `TripInput` из локальной анкеты. Затем `previews` с `{ kind: "generate_plan" }` (как в `api.js`). Индикатор загрузки; ошибки `503` (ML недоступен), `502`, `422` — человеческим текстом.

### Экран 8. Предпросмотр и сохранение
- Подпись «Черновик — ещё не сохранён», заголовок «Маршрут на N дня», переключатель дней (как `.days` в `app.css`), строка «Суббота · около 4,5 часа · 5,8 км пешком» из `totals` превью.

## 4. Как устроить код

- `index.html`: новые `<section class="screen onb" data-flow="...">` для экранов 1–5, 7, 8 (скрыты по умолчанию); `#screen-pick` переиспользовать.
- Новые модули: `js/session.js` (сессия, вход, выход, состояние гостя), `js/onboarding.js` (анкета: состояние, валидация, сохранение), `js/trip-setup.js` (экраны 5–8, сборка `TripInput`/`TripFromProfileRequest`). `api.js` — расширить экспортами `register`, `login`, `logout`, `getProfile`, `saveProfile`, `createTripFromProfile`; **CSRF после входа/выхода обновлять из ответа**.
- `app.js`: убрать хардкод `FAMILY`/`TRIP_INPUT`, вместо этого — запуск по машине состояний из раздела 2; `?newtrip=1` оставить для репетиции демо.
- `css/onboarding.css` — стили новых экранов на токенах из `app.css`.
- Тексты из данных — только через `textContent` (как в `pick.js`).
- Состояние анкеты держать одним объектом той же формы, что `FamilyOnboardingInput` (+ локальные имена детей отдельно) — чтобы гость и аккаунт шли через одну функцию сборки.

## 5. Приёмка

1. Новый пользователь: регистрация → 3 шага анкеты → новая поездка → (свайпы или пропуск) → пожелания → предпросмотр → «Сохранить» → открывается «Сегодня» с этим маршрутом.
2. Перезагрузка страницы после этого — сразу основной интерфейс, анкету и вход не спрашивает.
3. Вход с этим аккаунтом в другом браузере — анкету не спрашивает, сразу «Новая поездка»; в «Мои поездки» есть сохранённая.
4. Гость: анкета и поездка работают без аккаунта; после входа анкета сохранилась на сервер, поездка перешла в аккаунт.
5. Валидация: 0 детей / 3 ребёнка / возраст вне 3–11 / пароль < 15 символов / пожелания > 2000 — не отправляются, понятная ошибка.
6. `409 VERSION_CONFLICT` при сохранении анкеты — перечитать и показать «Анкета изменилась на другом устройстве».
7. Бэкенд недоступен — понятное сообщение; текущий запасной вариант `route-cache.json` для демо не ломать.
8. Всё работает на ширине 360–480 px, кнопки ≥ 44 px, у полей есть `<label>`.

## 6. Открытые вопросы (не решать самому — спросить Артёма/команду)

1. **Словарь интересов.** Бэкенд в `GET /reference-data` отдаёт только `history / science / play` (`internal/httpapi/trips.go`). Нужны id для 7 детских и 6 взрослых интересов, **согласованные с ML** (Вильдан) и добавленные Максимом в `reference-data`.
2. **Свайпы → обязательные места.** Карточки в `data/cards.json` имеют id из датасета кейса (`"57"`), а `selections` в поездке требуют `place_id` + `activity_id` из пула ML; чужие id дают `422 UNKNOWN_ACTIVITY`. Нужен маппинг карточка → место ML или отдельное поле в запросе (решает Максим/Вильдан). Пока — передавать выбранные места на карту (как сейчас) и не класть в `selections`.
3. **Часы в день → `duration_budget_sec`** и окно дня для `before_arrival` — согласовать значения с Максимом.
4. **Точка старта.** Геокодера адресов нет. Нужен ли он (и чей), или хватит геолокации, точки на карте и готового списка.
5. **Имя ребёнка** — хранить только на устройстве (предложение) или Максим добавит поле.

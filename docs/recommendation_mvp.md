# RecSys и подключение backend

Состояние на 21 ноября 2026 года. Новые поездки в Compose используют настоящий
`model-service`, каталог `city-enriched-v3`, модель `family-content-recsys-v2`.
Это работающий content baseline: локальные оценки интересов по анкете и тематике,
равные веса детей, ограничения допуска и MMR. Stravl checkpoint здесь не используется.
Глобальный оптимум маршрута и качество персонализации на реальных семьях не измерены.

## Данные для обслуживания запросов

`data/catalog/enriched/catalog.jsonl`: 1 174 места, 1 194 активности:
650 самостоятельных посещений, 321 приём пищи, 147 вариантов отдыха,
72 посещения туалета и 4 программы с 46 опубликованными сеансами.
Туалет в ресторане — отдельная короткая услуга, а не 45-минутный обед.
Еда, отдых и услуги дают нулевой вклад в баланс детских активностей.

Источник — `outputs/all_places_v2/` (1 357 записей мест и 30 программ).
85 дополнительных исходных строк, 90 неоднозначных соответствий и 8 организаций
без программы удержаны вне serving-каталога. Из 30 программ 24 требуют проверки
площадки, ещё 2 не имеют пригодного времени; используются 4 программы с проверенным
соответствием площадки. Никакие неизвестные расписания и координаты не придуманы.
Исходный экспорт сохраняется целиком. Причины и SHA: `data/catalog/enriched/manifest.json`.

Сеансы с конфликтом длительности, sold-out при сборе, неизвестным окончанием или
непроверенным сопоставлением площадки не поступают в выдачу. Прошедшие сеансы
отбрасываются по текущему времени API. Публикация не подтверждает наличие билетов:
`booking_status=unknown`. Наличие билетной страницы не доказывает обязательную
предварительную запись, поэтому `booking_required` также может быть unknown.
Маркировка 6+ отделена от жёсткого допуска и возрастной пригодности.

Свойства сети не назначаются филиалам. Общая страница «Сыроварни» без уверенной
привязки к адресу не подтверждает игровую комнату конкретной записи.
Сведения источника сохраняют URL, цитату, SHA, дату получения и
`verification_status=source_claim`; это не проверка посещением.

## Сценарии и HTTP-контракт

Основной контракт: `docs/contracts/openapi.json`; типы Go генерируются из него.
`POST /internal/v1/recommendations` принимает снимок семьи, policy, дни, selections,
версии, исключения, текущую дату/точку, spatial_scope и limit 1–50.

| purpose | Выдача |
|---|---|
| initial | Посещения и сеансы на даты поездки |
| restaurant | Приёмы пищи и семейные свойства заведений |
| along_route | Посещения/сеансы с фильтром коридора |
| toilet | Туалеты и отдельные туалетные услуги внутри заведений |
| rain | Места с опубликованным признаком помещения/укрытия; короткий отдых |
| playground | Детские площадки |
| rest | Скамейки, укрытия и места с известными сидениями |

`spatial_scope`: center+radius_m и/или route+corridor_width_m. Необязательный
`routes` — объединение нескольких реальных LineString без выдуманных соединений.
Координаты — [долгота, широта]. Поля `distance_m` и `distance_to_route_m` содержат
географическое приближение; направленные пути и фактическое время считает Go/Valhalla.

`restaurant_filters` задаёт children_menu, small_portions, play_area,
play_area_supervision (boolean/null). Неизвестный или сетевой признак не проходит
булев фильтр. Расписание персонала передаётся отдельно: наличие персонала не
обещает его присутствия во всё время работы. Сложные временные условия игровой
зоны требуют проверки источника. Короткая явная просьба «кафе с детским меню»
также распознаётся локально; неоднозначный текст помечается предупреждением.
Полные примеры запросов: `examples/recommendation-{initial,restaurant,event}.json`.

Ответ содержит до limit разных place_id, оценки детей, причины, evidence и
доступность на каждую дату. Разные программы одной площадки хранятся отдельно,
но в одном ответе выбирается одна активность на площадку. Явно выбранная активность
имеет приоритет; два выбора одного места дают SELECTION_CONFLICT. Неверный,
прошедший или не соответствующий дате occurrence_id также отклоняется явно.
Посещённые и исключённые activity_id не выдаются; запреты допуска не смягчаются score.

Публичные endpoint Go (cookie, CSRF и владение поездкой сохраняются):

- `POST /api/v1/trips/{id}/recommendations`: initial/restaurant/along_route,
  expected_version, date, request_text, exclude_activity_ids, limit,
  необязательный restaurant_filters. Семью и policy клиент не подменяет.
- `POST /api/v1/trips/{id}/needs`: tired/toilet/rain/hotel/playground.
  Для hotel нужен явный hotel_point; end_point не считается отелем.
  Для актуальной позиции point и observed_at передаются вместе.
- Помощник получает еду/инфраструктуру через RecSys; в явном demo-режиме сохранён
  прежний DB-провайдер. При отказе RecSys нет тихой подмены ответами mock.

Поиск не меняет Trip. Выбор проходит add_activity/replace_stop -> preview -> apply.
После внешнего вызова повторно проверяются версия и владелец. Реальные подходы,
обходы и исключение уже включённых в план мест проверяет backend. Устаревшие
версии дают 409, неизвестные данные — partial/no_candidates с предупреждениями,
отказ зависимости — 503, повреждённый ответ — 502.

## Календари и неизвестность

Часы нормализуются из сохранённых источников, только для области place/restaurant.
Часы кухни и персонала не становятся часами всего заведения. Противоречивые,
неподдержанные и условные расписания остаются unknown. Отсутствие дня в разобранном
подмножестве не считается доказательством закрытия. Ночные интервалы делятся по
границе даты; конец до полуночи ограничивается 23:59:59 из-за контракта v1.

Длительности обычного визита/еды/услуг — редакционные оценки. Конкретный сеанс
получает только опубликованную длительность; при необходимости окончание вычислено
из явного начала и этой длительности. Backend проверяет попадание и подход в сеанс.
Указанные часы/правила требуют подтверждения актуальности. Такие планы conditional,
предупреждения подтверждаются до apply, известные нарушения снять подтверждением нельзя.

## Запуск и совместимость

`.env.example` и Compose по умолчанию направляют новые поездки на RecSys:

```dotenv
MODEL_CATALOG_VERSION=city-enriched-v3
BACKEND_CATALOG_VERSION=city-enriched-v3
BACKEND_ML_URL=http://model-service:8080/internal/v1/recommendations
```

Существующие `city-osm-v2` обслуживаются тем же API по своей версии; mock-ml-v1
сохраняет прежний provider. Сохранённые ID/поездки не мигрируют автоматически.
GigaChat нужен для LLM-парсера/помощника, структурированные запросы RecSys работают
без него. ML_API_TOKEN, если задан, должен совпадать у backend и модели.

```bash
docker compose config --quiet
docker compose up --build -d
```

Полный стек требует PostgreSQL и подготовленной Valhalla, как раньше. Локальный
.env не заменять примером поверх ключей. Backend ожидает health модели.
Для отдельного запуска модели из корня репозитория:

```bash
PYTHONPATH=models .venv/bin/python -m uvicorn services.model_service.app:app --host 127.0.0.1 --port 8082
go run ./cmd/backend -ml-url http://127.0.0.1:8082/internal/v1/recommendations -catalog-version city-enriched-v3
```

`GET /health` модели проверяет каталог и сообщает SHA, версии, число записей/мест,
поддержанные purpose и сеансы. Он не подменяет `/healthz` Go.

## Проверка

```bash
.venv/bin/python scripts/build_recsys_catalog.py
PYTHONPATH=models:scripts .venv/bin/python -m unittest discover -s models -p 'test_*.py'
PYTHONPATH=models:scripts .venv/bin/python -m unittest discover -s scripts -p 'test_*.py'
go test ./...
.venv/bin/python scripts/check_mvp.py
.venv/bin/python scripts/check_recsys.py
```

Новый E2E запускает настоящий Python HTTP RecSys и Go backend: initial/restaurant/
along_route, меню, неизвестный фильтр, все needs, обязательный сеанс, preview/apply,
вставка еды с балансом/длительностью, контекстный выбор, версия, владение и отсутствие
мутации при поиске. Маршрутизатор — тестовый, LLM — структурированный test double;
это не проверка реальной Valhalla/PostgreSQL или качества естественного языка.
Отчёт: `data/processed/recsys/checks.json`. Прежний E2E проверяет совместимость v2.

При подключении Docker daemon был выключен. Compose config проверен; сборка и
запуск контейнеров и публичное развёртывание в этой работе не выполнялись.

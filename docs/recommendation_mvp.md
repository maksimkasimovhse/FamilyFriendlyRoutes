# MVP рекомендаций и подключения backend

Состояние на 21 ноября 2026 года. Расширение каталога отложено по запросу пользователя.

## Что работает

`model-service` реализует `POST /internal/v1/recommendations` по основному
`docs/contracts/openapi.json`. Это локальный content baseline на 281 объекте (165 из CSV и 116 из OSM) в `data/catalog/city/catalog.jsonl`, версия каталога `city-osm-v2`, модель
`city-content-baseline-v1`. Онлайн-запрос не загружает сайты. Понимание текста теперь подключается через
parser-service; [архитектура LLM-помощника](llm_assistant.md). Сам ранжировщик GigaChat не вызывает.
Stravl checkpoint здесь не используется.

Сервис сам строит оценки интересов по темам каталога и анкете, использует равные
веса детей, отдельный профиль возрастной пригодности, ограничения и MMR. Поддержаны
псевдонимы интересов текущей анкеты: `play`, `tech`, `museums`, `walks`, `local_food`.
Неизвестные ID интересов отмечаются предупреждением. Сопоставление тем эвристическое,
оценки не являются обученными вероятностями. Популярность пока нейтральная `0.5`.

Выбранные пользователем активности сохраняются даже при малом limit. Посещённые
и исключённые активности не возвращаются. Конфликт выбора с исключениями,
несуществующим ID или неподдержанным сеансом возвращается явно. Известный запрет
участия не компенсируется высоким интересом; источники известных ограничений
проверяются при загрузке каталога.

Полные запросы и ответы проверяются по OpenAPI, включая формат дат. Ответ содержит
оценки каждого ребёнка, `balance_credit`, причины, предупреждения и доступность
на каждую запрошенную дату. Нельзя получить больше 50 мест или задать другую
версию каталога. Планирование по дням и маршруты остаются в Go-backend.

## Неизвестные сведения

У исходного среза нет подтверждённых часов, допусков и возрастной пригодности.
Сервис сохраняет их неизвестными. Он не объявляет объекты открытыми весь день
и не назначает всем детям допуск `eligible`. Длительность самостоятельного
посещения берётся из `models/recommendation_policy.json` и помечается `estimated`.
Это стартовые продуктовые оценки, а не сведения организаторов.

Ответ имеет `status=partial`, а preview требует подтверждения предупреждений
о неизвестных часах, допусках, возрасте и оценённой длительности. Без подтверждения
apply отклоняется. Пустой пул имеет `status=no_candidates`; отказ сервиса остаётся
503 и не подменяется пустым списком.

Без настроенного parser-service `request_text` поддерживает только простой локальный словарь явных пожеланий:
например, «Хотим животных, без музеев». Распознанное мягкое исключение исключает
соответствующие необязательные места. Явный выбор пользователя имеет приоритет
с предупреждением о конфликте. Сложные фразы, даты и условия не угадываются:
неразобранная часть вызывает `REQUEST_TEXT_PARTIALLY_UNDERSTOOD`, которое надо
подтвердить перед apply. Это ограниченный адаптер, а не полноценное понимание
естественного языка.

Поддержан `purpose=initial` без пространственных фильтров. Рестораны по пути,
инфраструктура по срочной потребности и конкретные сеансы требуют своих адаптеров;
запросы таких функций получают `501 FEATURE_DISABLED`.

## Запуск

В Compose backend теперь направлен на `model-service:8080/internal/v1/recommendations`.
Mock вынесен в необязательный профиль `mock`. Версия каталога задаётся одинаковым
`MODEL_CATALOG_VERSION` для обоих сервисов. Общий `ML_API_TOKEN` включает Bearer
аутентификацию всех внутренних endpoint модели, кроме `/health`.

Для полного приложения нужны уже предусмотренные проектом PostgreSQL и
подготовленная Valhalla. Перед запуском заполнить пароль PostgreSQL в существующем
локальном `.env`, сохраняя остальные настройки. Не заменять `.env` файлом примера
поверх ранее добавленных ключей.

```bash
docker compose config --quiet
docker compose up --build -d
```

Health модели проверяет, что каталог читается и проходит валидацию, и возвращает
версию модели, версию/контрольную сумму каталога и число записей.

При запуске вне Docker, из корня репозитория:

```bash
PYTHONPATH=models .venv/bin/python -m uvicorn services.model_service.app:app --host 127.0.0.1 --port 8082
go run ./cmd/backend -ml-url http://127.0.0.1:8082/internal/v1/recommendations -catalog-version city-osm-v2
```

Для второго процесса всё равно нужен ранее подготовленный routing manifest и
запущенная Valhalla. `ML_API_TOKEN`, если задан, должен совпадать в обоих процессах.
Поездки предыдущих каталогов `mock-ml-v1` и `seed-city-v1` не переводятся молча на новый каталог: для проверки
нового MVP создать новую поездку. ID нового каталога: `place:main:<id>` и
`activity:main:<id>:visit`; старые mock ID не считаются псевдонимами этих записей.

## Воспроизводимая проверка

```bash
.venv/bin/python -m pip install -r services/model_service/requirements.txt 'httpx>=0.28,<1'
PYTHONPATH=models .venv/bin/python -m unittest discover -s models -p 'test_*.py'
.venv/bin/python scripts/check_mvp.py
go test ./...
```

`check_mvp.py` временно запускает настоящий Python API на свободном loopback-порту,
выполняет Go HTTP-тест и останавливает процесс. Проверяются подбор, обязательное
место, preview без записи, подтверждения неизвестности, apply, идемпотентность,
устаревшая версия, отказ ML без изменения сохранённой поездки и ошибка отсутствующего
выбора. Отчёт: `data/processed/mvp/checks.json`.

Маршрутизатор в этом сквозном тесте — `dayRouter`, тестовая реализация. Реальные
OSM-геометрия, сеть Compose и PostgreSQL этим тестом не проверяются. При выполнении
работ Docker daemon был выключен; выполнена проверка конфигурации Compose, сборка
образов и полный запуск контейнеров не выполнялись. Для приёмки реального стека:
запустить подготовленную Valhalla и Compose, затем выполнить существующий
`node scripts/smoke-backend.mjs` через работающий backend.

## Расширение исходного каталога

Первый проверенный этап включает 165 мест вместо исходных 40; набор ответа по-прежнему
ограничен 50. В каталоге удержаны школы без конкретной программы, управляющая
организация и объект вне городского сценария, объединён дубль парка. Прежний
срез `data/demo/` остаётся воспроизводимым fixture.
[Полный аудит источника и дополнительного CSV](../data/catalog/README.md).


## Версия с дополнительными OSM-объектами

Каталог `city-osm-v2` содержит 281 объект: прежние 165 и 116 новых из OSM.
API продолжает выдавать максимум 50 разных мест на поездку. Новые площадки
не означают наличие конкретных сеансов: для этого нужны отдельные данные.

Сквозной тест дополнен обязательным OSM-объектом «КидБург»: проверены его сохранение
в плане и подтверждение OSM_SOURCE_UNVERIFIED. Источники известных булевых свойств
и исходная дата OSM доходят до полного ответа backend. Новые активные записи не
получают автоматически возраст, доступность сейчас или бесплатный вход.

Для применения нового каталога создать новую поездку: старые версии не обновляются
молча. Подробный разбор добавленных и отложенных объектов — в
`data/catalog/city/osm_expansion_review.json`.

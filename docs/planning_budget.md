# Автоматический бюджет семейного маршрута

## Формула

```text
T_дня = min(duration_budget_sec, длина available_window при наличии)
T_ходьбы = max(0, T_дня − T_посещений − T_еды − T_отдыха − T_ожидания)
D_по_времени = V_км_ч × 1000 × T_ходьбы / 3600
D_основных_точек = max(0, min(M, D_по_времени) − P)
```

В API расстояния передаются в метрах, время — в секундах. M — общий дневной пеший лимит семьи. P — резерв расстояния на заходы в рестораны. Время еды и P — независимые параметры: время визита не переводится в дополнительный пеший крюк.

Пример: день 8 часов, посещения 4 часа, еда 1,5 часа, отдых 0,5 часа, ожидание 0. Для M=6000 м, V=2,5 км/ч, P=1000 м остаётся 2 часа ходьбы, или 5000 м. Основные точки получают `min(6000, 5000) − 1000 = 4000 м`.

## Где менять константы

Все значения находятся в [planning_defaults.json](../internal/planner/planning_defaults.json). Формула и подстановка — в [budget.go](../internal/planner/budget.go). После изменения JSON нужно пересобрать/перезапустить backend; при изменении политики следует поменять policy_version.

### Возрастной лимит M по умолчанию

| Возраст | Метры в день |
|---|---:|
| 3 | 2000 |
| 4 | 2500 |
| 5 | 3000 |
| 6 | 3500 |
| 7 | 4000 |
| 8 | 4500 |
| 9 | 5000 |
| 10 | 5000 |
| 11 | 5000 |

Если `max_walk_distance_m_per_day=null`, берётся меньшее значение среди детей. Например, для детей 4 и 10 лет — 2500 м. Числовое значение пользователя имеет приоритет и не ограничивается возрастным дефолтом. Неизвестный или неподдерживаемый возраст не заменяется произвольным значением: текущая аудитория 3–11 лет проверяется валидатором.

### Скорость и еда

| Параметр | Значение |
|---|---:|
| relaxed | 2,5 км/ч |
| standard | 3 км/ч |
| intensive | 3,5 км/ч |
| quick_service | 60 минут на визит |
| table_service | 75 минут на визит |
| meal_with_play | 105 минут на визит |
| Число визитов по умолчанию | 1 |
| Формат по умолчанию | table_service |
| P по умолчанию | 0 м, пока семья не задала резерв или команда не изменила константу |

Значения — настраиваемые продуктовые гипотезы для проверки на семьях. Это не измеренные нормы городского туризма для каждого года жизни. Для длительности ресторанного визита нет достаточного основания вводить отдельные значения для каждого возраста.

В качестве ориентиров использованы разные по контексту источники: [WTA о семейных походах](https://www.wta.org/go-outside/kids/backpacking-with-kids), [рекомендации регионального Роспотребнадзора](https://www.13.rospotrebnadzor.ru/content/o-rekomendaciyah-kak-pravilno-organizovat-pohod-s-uchastiem-detey-1), [Alpenverein о ходьбе с детьми](https://www.alpenverein.at/klagenfurt/home/topnews/AVJ-Wandern-mit-Kindern.php). Эти материалы не доказывают приведённые выше точные дефолты. В [наблюдении семей в ресторанах быстрого питания Торонто](https://www.sciencedirect.com/org/science/article/abs/pii/S174736161800001X) средний визит составлял 53 минуты, включая занятия помимо еды; это не возрастная таблица для ресторанов Нижнего. Выбранные нами скорости, лимиты и длительности требуют последующей калибровки.

## Автоподстановка и переопределения

В `LoadLimits`:

```json
{
  "pace": "relaxed",
  "max_walk_distance_m_per_day": null,
  "max_continuous_walk_duration_sec": 3600
}
```

M определяется по детям, P — по конфигурации. Чтобы переопределить их, передать числа в `max_walk_distance_m_per_day` и `restaurant_walk_reserve_m_per_day`. Проверяется `0 ≤ P ≤ M`.

Дополнительные поля конкретного дня:

```json
{
  "meal_count": 2,
  "meal_format": "quick_service",
  "rest_budget_sec": 1800
}
```

Это резервирует 2 × 3600 = 7200 секунд еды и 1800 секунд отдыха. Если meal_count/meal_format отсутствуют, используются конфигурационные значения.

`meal_duration_sec` — общий дневной override, который имеет приоритет над count × format. Например, 5400 означает 90 минут еды суммарно за день, а не на каждый ресторан. Явный 0 выключает резерв еды. `meal_count=0` также выключает его, если override не передан.

Рассчитанные дефолты возвращаются в TripView.input. Новая генерация не мутирует переданный объект или сохранённый снимок поездки до apply.

## Как формула применяется к точкам

1. ML возвращает до 50 мест с активностями, длительностями и доступностью.
2. Для каждой пробной вставки backend рассчитывает реальные направленные OSM-переходы, посещения и ожидания по расписанию.
3. Формула пересчитывается с новым составом дня. Расстояние включает старт и возвращение к финишу.
4. Необязательная точка принимается, если маршрут помещается в новый бюджет и не нарушает известные ограничения.
5. Обязательная точка не удаляется ради формулы: при нарушении возвращается infeasible и запрещается apply.

Распределение снова учитывает время через формулу. Прежнее правило «время не влияет на состав кластеров» заменено этим решением. Эвристика не гарантирует глобально оптимальный порядок.

## Отсутствие двойного учёта

- Посещения visit/session/utility учитываются как время посещений.
- Для meal берётся максимум между запрошенным временем еды и длительностью уже включённых meal-остановок.
- Для rest аналогично берётся максимум между rest_budget_sec и длительностью rest-остановок.
- Только ещё не покрытый реальными остановками остаток добавляется в суммарное время дня.

Если остался неразмещённый резерв еды/отдыха, возвращается UNSCHEDULED_BREAKS. Он входит в totals.elapsed_duration_sec, но конкретные места и интервалы этих перерывов ещё не выбраны. Расчётные часы отдельных остановок пока не являются полным расписанием с расположенным во времени обедом. Конкретное meal_window остаётся неподдержанным и отклоняется явно.

## Что возвращается для проверки

`DayPlan.totals` содержит:

- walk_budget_m — M;
- restaurant_walk_reserve_m — P;
- walking_speed_kph — V;
- walking_time_budget_sec — T_ходьбы;
- time_limited_walk_budget_m — расстояние по доступному времени;
- primary_walk_budget_m — окончательный результат формулы;
- visit_duration_sec, meal_duration_sec, rest_duration_sec, wait_duration_sec;
- walk_distance_m и walk_duration_sec — реально рассчитанные переходы;
- elapsed_duration_sec — суммарное время, включая ещё не размещённые резервы;
- budget_policy_version — версия набора констант.

P вычитается один раз, после min. Он не добавляется к фактическому пройденному расстоянию. Числовой бюджет не заменяет проверку конкретного OSM-пути и расписания.

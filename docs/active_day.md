Актуальное уточнение 21.11.2026: вместимость ограничена только временем пользователя (до 3 ч, 4–5 ч, весь день), с учётом реальных OSM-переходов, посещений и сеансов. Километраж справочный. Старые упоминания лимитов ходьбы, возрастных норм и формулы M/P ниже отменены; см. [правила бюджета](planning_budget.md).

# Продолжение прогулки и пересчёт оставшегося маршрута

## Реализованный сценарий

1. Получить и применить исходный generate_plan preview.
2. Подтвердить фактическую точку и время старта через start_day preview/apply.
3. Отметить следующую остановку как visited через progress.
4. Удалить следующую необязательную точку через remove_stop preview.
5. Просмотреть изменения пути/времени и применить вариант через apply.

Каждый этап работает с сохранённой поездкой. Перезапуск backend не теряет старт, посещения и историю. Хранилище исполнения сейчас остаётся однопроцессным JSON-store; добавленные в репозитории таблицы каталога не означают, что поездки уже перенесены в PostgreSQL.

## Запросы для frontend

Все POST требуют cookie сессии, X-CSRF-Token и application/json. Создание поездки, progress и apply требуют Idempotency-Key. Для preview ключ необязателен.

### Начало дня

Пример JavaScript-тела POST `/api/v1/trips/{trip_id}/previews`:

```js
{
  expected_version: trip.version,
  command: {
    kind: 'start_day',
    date: day.date,
    point: actualStartPoint,
    start_at: new Date().toISOString()
  },
  current_position: null,
  observed_at: null
}
```

Start_at должен относиться к выбранной московской дате и не быть позже серверного времени более чем на минуту. Старт не может предшествовать available_window. Исходное время окончания сохраняется; длительность ограничивается оставшимся доступным окном. Повторный старт того же дня отклоняется. Следующий день можно начать, когда в ранее начатых днях не осталось planned-активностей; после этого их progress больше не редактируется.

Preview не меняет сохранённый Trip. Для сохранения POST `/api/v1/trips/{trip_id}/previews/{preview_id}/apply`:

```js
{
  expected_version: preview.base_version,
  acknowledged_warning_codes: preview.required_acknowledgement_codes
}
```

После apply только выбранный день получает clock и execution. Будущие дни не становятся активными и не получают почасовое представление автоматически.

### Отметка посещения

POST `/api/v1/trips/{trip_id}/progress`:

```js
{
  expected_version: trip.version,
  date: day.date,
  stop_id: nextStop.stop_id,
  status: 'visited',
  observed_at: new Date().toISOString()
}
```

Отметить можно только следующую planned-остановку активного дня. Уже сохранённые visited/skipped неизменяемы. Время монотонно и не находится в будущем более чем на минуту.

Visited подтверждает прохождение рассчитанного сегмента к остановке. Счётчик километров берётся из сохранённого OSM-leg, а не из GPS. Длительности завершённых посещений и категорий тоже являются оценками исходного плана. Реальное прошедшее время берётся из observed_at относительно started_at.

Progress повышает версию, обновляет execution, оставшиеся бюджеты и семейный баланс. Геометрия и порядок остановок не пересчитываются. Для повтора запроса использовать тот же Idempotency-Key и то же тело, включая observed_at: повтор не списывает километры дважды.

Status='skipped' не подтверждает движение к пропущенной остановке. Текущая точка и пройденные километры не меняются; выставляется execution.needs_replan. Перед следующей отметкой нужно применить replan_day preview. Пропуск обязательной остановки запрещён.

### Удаление следующей точки

POST `/api/v1/trips/{trip_id}/previews`:

```js
{
  expected_version: trip.version,
  command: {
    kind: 'remove_stop',
    date: day.date,
    stop_id: nextStop.stop_id
  },
  current_position: null,
  observed_at: null
}
```

Удаляется только planned и необязательная остановка. Backend сохраняет подтверждённую историю и пересчитывает оставшийся список в текущем порядке. Удалённая точка не заменяется автоматически новой рекомендацией. Другие дни сохраняются без изменений.

Diff содержит removed_stop_ids, changed_dates и изменения времени, когда они вычислимы. До apply сохранённая поездка остаётся прежней.

### Пересчёт без удаления

Используется команда `{kind: 'replan_day', date: day.date}` с актуальной expected_version. Она нужна, например, после skipped или прошедшего времени. Новый запрос к ML не выполняется: часы и сеансы берутся из сохранённого Stop.availability. Устаревший реальный план без снимка доступности нужно сначала обновить исходной генерацией.

При current_position=null используется последняя подтверждённая точка, с предупреждением LAST_CONFIRMED_POSITION. Переданная точка пока должна иметь те же координаты. Произвольное GPS-перемещение отклоняется как UNACCOUNTED_MOVEMENT: без трека/дополнительных подтверждений нельзя молча обнулить потраченные километры. При observed_at=null используется серверное текущее время, не раньше последней отметки.

## Остаток бюджета

```text
spent_time = observed_at − started_at
M_remaining = max(0, M_original − consumed_walk_distance_m)
T_remaining = max(0, T_original − spent_time)
meal_remaining = max(0, meal_budget − consumed_meal_duration_sec)
rest_remaining = max(0, rest_budget − consumed_rest_duration_sec)

D_remaining = max(0, min(M_remaining, V × T_walk_remaining) − P)
```

T_walk_remaining получается из T_remaining вычитанием только будущих посещений, будущего ожидания и ещё не покрытых резервов еды/отдыха. Исторические посещения не вычитаются второй раз. Исходные дневные параметры в TripInput не заменяются остатком: повторный replan не списывает прошлое повторно.

P пока остаётся полным резервом для будущих ресторанных заходов. Подбор и добавление конкретного ресторана с расходованием этого резерва — отдельный этап. Приём пищи вне отмеченных meal-остановок не выводится автоматически из паузы между отметками; его резерв сам не обнуляется.

В execution доступны started_at, observed_at, current_point, completed_leg_ids, needs_replan, оценки потраченных километров и длительностей, а также реальное прошедшее elapsed_duration_sec.

В totals.remaining_walk_distance_m и remaining_duration_sec возвращается бюджет перед планированием оставшегося списка, а не свободный остаток после всех будущих остановок. Primary_walk_budget_m относится к оставшейся части; walk_budget_m сохраняет исходный дневной M.

Общие totals содержат историю и будущий план. Для активного дня totals.elapsed_duration_sec = наблюдаемое прошедшее время + расчётная длительность оставшейся части. Поэтому сумма оценочных исторических категорий может отличаться от реального прошедшего времени; это не GPS-трек и не измерение времени внутри каждого места.

## История и карта

- Подтверждённые остановки и completed legs сохраняются без изменения геометрии и прежних ID.
- Новые legs получают отдельные ID с версией плана и соединяют последнюю подтверждённую точку с остатком и финишем.
- Skipped остаётся в истории, но движение к нему не считается совершённым. Его старый неподтверждённый переход не сохраняется как пройденный.
- После пропусков legs не обязательно равно stops+1. Frontend рисует реальные сегменты и их from/to; прямые линии между несвязанными точками не добавляются.
- Окончание всех активностей не подтверждает автоматически возвращение в отель и не переводит Trip в completed. Подтверждение финального перемещения — отдельный будущий сценарий.

## Версии и ошибки

Типичная цепочка версий: draft=1 → generate/apply=2 → start/apply=3 → visited=4 → remove/apply=5. Preview сам версию сохранённой поездки не меняет.

Для активного дня preview истекает через 30 секунд от observed_at. Apply повторно проверяет версию, срок, известные окна и временной запас. Уже прошедшее время первой исторической остановки не делает корректный оставшийся маршрут устаревшим. Если показанный вариант больше не подходит, backend возвращает ошибку и не заменяет его другим незаметно.

| Код | Смысл |
|---|---|
| VERSION_CONFLICT | Поездка изменилась после расчёта, в том числе из-за progress |
| PREVIEW_EXPIRED / PREVIEW_STALE | Пересчитать вариант и снова показать пользователю |
| DAY_NOT_STARTED / DAY_ALREADY_STARTED | Некорректный переход состояния дня |
| PROGRESS_ORDER / HISTORY_IMMUTABLE | Нельзя изменить подтверждённое прошлое или отметить точку вне очереди |
| MANDATORY_STOP | Нельзя пропустить или удалить обязательную точку обычной командой |
| REPLAN_REQUIRED | После пропуска сначала применить пересчёт |
| UNACCOUNTED_MOVEMENT | Новая позиция требует отдельного учёта пройденного пути |
| CATALOG_SNAPSHOT_REQUIRED | В старом плане нет сохранённых данных доступности |
| DAY_FINISHED | Доступное время дня исчерпано |
| ROUTING_UNAVAILABLE | Геометрия не рассчитана; сохранённый план остаётся прежним |

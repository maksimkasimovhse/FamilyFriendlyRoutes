Актуальный интерфейс: при регистрации и заполнении анкеты детей/родителей вопросов о сне нет. Сон задаётся только на экране «Когда и откуда гуляем?» для конкретной поездки. Старое поле family.nap сохраняется в API для совместимости.

# Дневной сон в семейном маршруте

В анкете family.nap — необязательные start_time/end_time в ЧЧ:ММ по Москве. null/отсутствие означает, что сон не нужен. Настройка сохраняется в семейном профиле аккаунта и в локальной анкете гостя. В поездке пользователь отдельно подтверждает адрес жилья; точка старта не подставляется молча. Каждый выбранный день получает DayInput.nap с точными window и location; null отключает сон для конкретного дня.

Планировщик разделяет выбранные места на утреннюю и вечернюю части, учитывает часы работы/сеансы и обе реальные OSM-дороги: старт → утренние места → жильё, жильё → следующие места → финиш. Если выполнимо, предпочтение отдаётся вариантам с посещениями и до, и после сна, а не всем местам только утром. Сон — обязательная синтетическая остановка kind=nap/category=lodging, а не ML-рекомендация и не карточка. Она не считается туристическим местом для минимума автоподбора. Удаление, пропуск и перенос сна через обычные команды запрещены.

Утреннее возвращение должно быть не позже начала сна. Обратный поиск в доступном окне дня рассчитывает latest_start_at с проверкой музеев и сеансов. В предварительном плане показывается «Начните до …, чтобы вернуться в жильё к …»; другие места подписаны «До сна / После сна». Это оценка по известным данным, а не гарантия: неизвестные часы работы остаются предупреждением. На экране «Сегодня» видны расчётные часы.

Бюджет 3/5/8 часов — outing_duration_sec: посещения, переходы в жильё и обратно и ожидание сеансов. Сон nap_duration_sec и ожидание в жилье до начала сна не расходуют этот бюджет. elapsed_duration_sec — полная календарная длительность с ними; финиш вычисляется по этому полю. Для короткого дня и балансировки используется outing_duration_sec. Конец available_window не переносится. Километровых лимитов нет.

В «Начать день» берутся фактическое время и доступная геопозиция. Если GPS недоступен, указанная точка старта явно показывается перед подтверждением. Непомещающиеся утренние места могут перейти после сна; если весь набор не помещается, preview предлагает убрать необязательные места. UI перечисляет удаления и сохраняет только после «Начать с этим планом». Активный пересчёт хранит посещённые остановки и пройденные сегменты. Завершение сна нельзя отметить до end_at; после завершения новый сон не вставляется и его время не списывается второй раз. Если время сна уже прошло, надо отключить его для этого дня до построения; произвольно переносить сон система не будет.

OpenAPI — источник истины: NapPreference, NapBreak, NapDayInfo. Старые поездки без nap работают как раньше; адрес жилья не записывается в постоянную семейную анкету. При изменении анкеты уже сохранённые поездки не изменяются.

Проверки: go test ./...; node --test frontend/js/nap-display.test.mjs; node scripts/smoke-nap-multiday.mjs (локальные ML/OSM, отдельная гостевая сессия).

На экране «Когда и откуда гуляем?» вопрос «Нужен дневной сон?» виден всегда, после выбора длительности прогулки. Анкета семьи задаёт только начальные значения; сон можно включить, отключить и изменить его время непосредственно для поездки, даже если в старой анкете его не было. Настройка поездки не меняет постоянную анкету.

# Геолокация с телефона через HTTPS

Компьютер и телефон должны быть в одной Wi-Fi-сети. Геолокация браузера требует доверенного HTTPS и разрешения пользователя. Обычный HTTP по локальному IP не подходит; localhost на телефоне означает сам телефон.

## Запуск на Windows

Из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-phone-https.ps1
```

Скрипт выбирает Wi-Fi IPv4, сохраняет публичные параметры Caddy в локальном `.env`, собирает backend, запускает Caddy и печатает два адреса. Если IP определён неверно:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-phone-https.ps1 -LanIP 192.168.1.10
```

По умолчанию приложение: `https://<IP>:8443`; получение публичного сертификата: `http://<IP>:8088/root.crt`. Образ Caddy загружается обычным `docker compose --profile https pull caddy`, если его ещё нет локально. Последующие запуски без сборки: добавить `-SkipBuild`. Старый адрес `http://localhost:8000` продолжает работать на компьютере.

## Один раз на iPhone

1. В Safari открыть напечатанный HTTP-адрес `/root.crt` и скачать профиль сертификата Caddy именно с этого компьютера.
2. В настройках открыть загруженный профиль (либо «Основные → VPN и управление устройством») и установить его.
3. Открыть «Основные → Об этом устройстве → Доверие сертификатам» и включить полное доверие корневому сертификату Caddy.
4. Открыть напечатанный HTTPS-адрес, нажать «Где я» или срочный сценарий и разрешить геолокацию.

Одного обхода предупреждения браузера недостаточно. На Android установить этот же корневой сертификат как сертификат ЦС в настройках безопасности; названия пунктов зависят от производителя и версии системы. Установка доверия выполняется владельцем телефона, скрипт не меняет хранилища сертификатов устройств.

## Если телефон не подключается

- Проверить совпадение Wi-Fi, IP и портов. Гостевые/общественные сети могут запрещать соединения между устройствами.
- В Windows Firewall разрешить входящие TCP 8443 и 8088 только для нужной локальной сети. Скрипт не меняет firewall автоматически. Если это домашняя сеть с профилем Private, администратор может добавить правило:

```powershell
New-NetFirewallRule -DisplayName 'FamilyFriendlyRoutes phone HTTPS' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443,8088 -RemoteAddress LocalSubnet -Profile Private
```

- Проверить `docker compose --profile https logs --tail 60 caddy web backend`.
- После смены Wi-Fi/IP повторить запуск с новым IP. Если удалён Docker-volume `caddy-data`, сертификат нужно установить заново: этот volume сохраняет ключи локального центра сертификации.

## Как устроено

Caddy (`https` profile) слушает только выбранный LAN-IP; HTTP-порт выдаёт только публичный `root.crt`, без приложения и без приватных ключей. HTTPS проксируется в `web:8001`, внутренний порт nginx, который не опубликован на компьютере. Оттуда запросы идут к непубличному `backend:8080`. nginx явно выставляет `X-Forwarded-Proto: https`; обычный вход 8000 выставляет `http`, игнорируя подставленные клиентом заголовки. Флаг backend `-trust-proxy-headers` включён только в Compose за этим доверенным прокси. Это сохраняет проверку Origin/CSRF и устанавливает Secure-cookie на HTTPS. Не публиковать порт backend при включённом флаге.

`.env`, экспортированный сертификат и приватные ключи не коммитятся. Публичного туннеля здесь нет; для демонстрации через интернет нужен отдельный домен/деплой.

Источники: [Geolocation API — MDN](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API), [Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https), [доверие установленным сертификатам на iOS — Apple](https://support.apple.com/en-ie/102390).

Проверка после запуска: `node scripts/smoke-phone-https.mjs` проверяет TLS с корневым сертификатом (без отключения проверки), Secure-cookie, Origin/CSRF и отдачу SVG. Создаёт тестовый черновик в отдельной гостевой сессии.

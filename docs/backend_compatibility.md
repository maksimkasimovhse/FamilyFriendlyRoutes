# Исправление совместимости backend и LLM

21 ноября 2026 года. При внешней диагностике стенда `/health`, `/model/health` и
`/parser/health` отвечали 200, а `/api/v1/session`, `/api/v1/reference-data` и
`/api/v1/auth/me` — 404 с телом FastAPI `{"detail":"Not Found"}`. Это означает,
что публичный запрос не получил обработчик Go. Без доступа к запущенному окружению
невозможно установить, какой именно установленный upstream или образ оказался старым.

При сравнении ML-ветки с прежним backend также найдены нарушения совместимости:
замена источника рекомендаций и версии каталога по умолчанию, отключение mock-api,
обязательное подключение LLM к обычной генерации и новые требования токена к ранее
доступным внутренним rankings/parser endpoint. Они исправлены отдельно от симптома 404.

## Владельцы URL и порты

| Путь | Обработчик |
|---|---|
| `/api/v1/session`, `/api/v1/auth/*`, `/api/v1/profile/*`, `/api/v1/trips*`, `/api/v1/map/*` | Go backend |
| `/api/v1/trips/{id}/assistant/messages` | Go backend; внутренний вызов parser-service |
| `/api/v1/rankings` | Прежний отдельный proxy в model-service `/internal/v1/rankings` |
| `/parser/health`, `/model/health` | Диагностика отдельных Python-сервисов |
| `/healthz` | Проверка именно Go backend |

Go backend опубликован только на loopback `127.0.0.1:8083`, отдельно от parser 8081,
model 8082 и mock 8090. Публичный nginx направляет `/api/` прямо на 8083, сохраняя
точный прежний exception для rankings. Внутренний web-контейнер продолжает обращаться
к `backend:8080`; `/api/` не направляется в parser/model.

У Go `/healthz` есть заголовок `X-Family-Routes-Service: backend`. Compose healthcheck
запускает `backend -healthcheck`, работающий и в distroless-образе без curl/wget.
Web ожидает готовности Go. Проверка обычного `/health` Python больше не выдаётся за
проверку работоспособности публичного Trip API.

## Совместимые настройки

После подключения RecSys по явному запросу пользователя новые поездки по умолчанию
получают `city-enriched-v3` и model-service. Прежний mock-api сохранён для старых поездок.
Сохранённая поездка выбирает provider по своей версии каталога: `mock-ml-v1`
обслуживается mock-api, `city-osm-v2` и `city-enriched-v3` — model-service.
ID и версии сохранённых поездок не меняются молча.
Недоступность дополнительной модели не мешает чтению поездок, сессиям и входу.

Текущая конфигурация новых поездок:

```dotenv
BACKEND_ML_URL=http://model-service:8080/internal/v1/recommendations
BACKEND_CATALOG_VERSION=city-enriched-v3
MODEL_CATALOG_VERSION=city-enriched-v3
```

`ASSISTANT_URL` включает чат, но сам по себе не включает LLM в обычную генерацию.
Начальный разбор включается отдельно `INITIAL_LLM_ENABLED=true` или `-initial-llm`.
`REQUEST_PARSER_URL` по умолчанию пуст: model-service получает уже разобранный запрос
от backend либо работает своим ограниченным локальным адаптером. Для явного вызова
parser из model-service в Compose можно указать его внутренний service URL.

`ML_API_TOKEN` защищает новые service endpoint. Старые `/rankings`, `/request-parses`
и `/catalog-extractions` сохраняют прежний способ вызова. После перевода их клиентов
на Bearer auth можно явно включить `ML_REQUIRE_LEGACY_AUTH=true`. Cookie, CSRF,
проверка владельца поездки, версии и подтверждение предупреждений в Go API сохранены.

## Восстановление на машине стенда

Сначала исправление должно попасть в ветку, которую разворачивает стенд. Штатный
`family-routes-deploy.timer` в этом репозитории отслеживает `origin/main`;
одноразовое переключение серверной копии на ML-ветку таймером не сохраняется.
После получения коммита с исправлением в рабочую копию:

```bash
bash ops/restore-backend.sh --nginx-config auto
```

Скрипт собирает и поднимает Go backend, RecSys, прежний mock-api и web без зависимости
от ключей LLM. Сначала проверяет настоящий Go и `/api/v1/reference-data` через
web, затем делает резервную копию обнаруженного HTTP virtual host и проверяет
`nginx -t` перед reload. Если конфиг не найден однозначно, нужно передать путь
существующего активного HTTP-конфига вместо `auto`. TLS-конфигурация автоматически
не заменяется. Без `--nginx-config` проверяется и восстанавливается только Compose.
Данные, тома и git-ветка скриптом не удаляются и не переключаются.

Вызов на стенде здесь не выполнен: текущая SSH-учётная запись не получила доступ,
а пользователь подтвердил работу через локальную копию. Исправление в Git само по
себе не означает, что действующий nginx или контейнеры уже обновлены.

## Регрессионные проверки

Go-тесты проверяют прежние session/trip/preview запросы при отказе LLM, сохранение
CSRF, выбор старого и нового каталога, а также отбрасывание health от другого сервиса.
Python-тесты проверяют прежние anonymous rankings/parser вызовы и явное включение
новой авторизации. Сквозной `check_mvp.py` по-прежнему проверяет явное включение LLM
для начального планирования с настоящим model-service.
